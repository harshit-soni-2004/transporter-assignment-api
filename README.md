# Transporter Assignment on Lanes

A Spring Boot 3 / Java 17 REST API that solves the **Transporter Assignment on Lanes** optimisation problem: given a set of transport lanes and a pool of transporters who have each submitted price quotes for a subset of those lanes, find the minimum-cost assignment of transporters to lanes subject to a user-supplied cap on how many distinct transporters may be used.

## Problem Interpretation

> *"Select at most **k** transporters from the pool such that every lane is covered by at least one of the selected transporters, and the sum of the cheapest available quote for each lane is minimised."*

Each lane must be assigned to **exactly one** transporter (the cheapest among the selected set who quoted that lane). A transporter is "selected" if it wins at least one lane. The goal is to minimise total transportation cost while using **at most k** distinct transporters.

---

## Assumptions

1. **Lane IDs are user-supplied** – they are not auto-generated by the database.
2. **A transporter need not quote every lane** – lanes without a quote from a given transporter are simply unavailable under that transporter.
3. **Every lane must have at least one quote** – otherwise no feasible assignment exists regardless of k.
4. **All quotes must be strictly positive** (> 0).
5. **Input is replaced atomically** – posting to `/input` wipes the previous dataset before writing the new one.
6. **In-memory H2 by default** – data is lost on restart; use PostgreSQL for persistence (see environment variables).
7. **Tie-breaking** – when two subsets yield the same minimum cost, the one that uses more transporters is preferred (fairer distribution).

---

## Algorithm

### Approach – Exact Bitmask Enumeration

The solver enumerates all **2ⁿ subsets** of the transporter pool, pruning those with more than *k* members. For each feasible subset it:

1. Checks whether every lane has at least one quote in the subset.
2. For each lane, picks the cheapest transporter in the subset.
3. Accumulates total cost and tracks the best result.

**Complexity**: `O(2ⁿ × L × n)` where:
- `n` = number of transporters
- `L` = number of lanes

**Guard**: `n > 20` is rejected with HTTP 400. At n = 20 there are ≈ 1 M subsets; beyond that an ILP or column-generation approach would be required.

**Minimum-required-transporters check**: before the main enumeration the solver computes the smallest *m* such that some subset of size *m* covers all lanes. If `m > k` the solver raises an `InfeasibleException` (HTTP 422) immediately, without touching the full enumeration.

## Known PDF Inconsistencies

The original problem PDF contains sample data and expected answers that do **not** match each other:

| Issue | Detail |
|-------|--------|
| **10-lane example**: Lane 7 assigned to T2 | T2 has **no quote** for Lane 7 in the data table, so this assignment is impossible. |
| **10-lane example**: stated total 29 000 | The sum of the per-lane costs shown does not add up to 29 000; the arithmetic is inconsistent. |
| **5-lane example**: stated answer | Does not match the optimal solution computed by the bitmask solver on the same input. |

Correctness is validated by unit tests that run the solver against hand-verified inputs.

## Environment Variables (PostgreSQL / Prod)

| Variable | Default | Description |
|----------|---------|-------------|
| `DB_URL` | `jdbc:h2:mem:transporterdb;...` | JDBC URL |
| `DB_USERNAME` | `sa` | Database username |
| `DB_PASSWORD` | *(empty)* | Database password |
| `DB_DRIVER` | `org.h2.Driver` | JDBC driver class |
| `DB_DIALECT` | `org.hibernate.dialect.H2Dialect` | Hibernate dialect |

### PostgreSQL example

```bash
docker run -p 8080:8080 \
  -e DB_URL="jdbc:postgresql://db-host:5432/transporterdb" \
  -e DB_USERNAME=postgres \
  -e DB_PASSWORD=secret \
  -e DB_DRIVER=org.postgresql.Driver \
  -e DB_DIALECT=org.hibernate.dialect.PostgreSQLDialect \
  transporter-assignment:latest
```

> **Note**: Change `spring.jpa.hibernate.ddl-auto` to `update` or `validate` in production to avoid dropping the schema on every restart.
